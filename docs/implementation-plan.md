# Implementation Plan

Product rules are in [`PRD.md`](./PRD.md); vocabulary in [`CONTEXT.md`](../CONTEXT.md); decisions in [`docs/adr/`](./adr/). This file orders the work and tracks status. It changes often; the PRD should not.

**Current step: 17 (Map View).** Steps 0 to 16 are done (including 12b). The final design is in [`docs/design/`](./design/); a few designer fixes are pending and do not block step 0.

## Working agreement

- Work in thin vertical slices: each step delivers one visible behavior across data, logic and UI, and leaves the system working.
- One commit per step; the commit message starts with the step number, for example `step 3: show Events on the time axis`.
- Rules (Leg lifecycle, overlap layout, Todo deletion) are written test-first with Vitest, before the UI that uses them.
- External services (Google Maps, Claude, Auth0) start behind a small interface with a fake implementation; the real one is its own step.
- Everything committed is in English.
- Before each commit, `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` all pass.
- At the end of each step, say how to check the new behavior in the browser.

## Stack

React, TypeScript and Vite (web); Node.js, TypeScript and Express 5 (API); PostgreSQL with Drizzle ORM; Zod schemas in a shared package; dnd kit; Auth0; Google Maps Platform; Claude API; Vitest; Docker on fly.io. Layout: npm workspaces `apps/web`, `apps/api`, `packages/shared`.

- [x] **16. Opening hours.** On request, read-only usual opening hours for an Attraction or Meal with a place, shown in the panel, and one general "Opening hours may conflict" label when the Event's time does not fit them. Product rules: PRD §3.5; design: panels 04, 05, 06, 07, 18 and the amber label on the card in 04. *Needs:* 14, 3.
  - **First, check the terms.** Before building the cache part, read Google's terms on caching opening hours (and the SKU and price of the hours fields). If hours may be cached 30 days (ADR 0007), do the steps below. If not, drop the persistent card label: the hours are fetched live on the button and the conflict shows only in the panel, and PRD §3.5 and ADR 0007 are updated to say so.
  - **Data.** The place provider gains `openingHours` (weekly periods as Google gives them: weekday, hour, minute for open and close; or "always open") and `businessStatus`, read from `regularOpeningHours` and `businessStatus` of Place Details (New). Search does not request them. They are cached in `places` with the same 30-day refresh as the rest of the place (ADR 0007). `currentOpeningHours` (next 7 days, holiday exceptions) is not used in this step. The fake provider returns fixed sample hours (24 hours, a weekly closure, a lunch break, an overnight period, no hours) so every case can be tried and tested.
  - **Event.** A boolean `openingHoursOn` (default false), shared by everyone on the Trip. The API sets it when the user presses the button (the server fetches the hours into the cache then, and answers that the place has none if so, leaving it off) and clears it when the Event's place changes or is cleared (server-side, with the other Event and Leg updates) and on "Remove opening hours". A kind change leaves it alone. The hours are read through the place cache with the Event's place; stale ones are fetched again when a Trip is loaded, once per place and only for Events that have it on, and a failure shows no hours and no label until the next try.
  - **Rule (test-first, in `packages/shared`).** A pure function takes the Event's start and duration, the Day's date, the hours and the business status, and returns whether there is a conflict. It handles several periods in a day, periods past midnight (including the early hours of the next day), 24-hour places, closed days, an Event running past midnight (checked up to midnight, as the axis cuts it) and a Trip without a start date (never a conflict). The weekday comes from the start date plus the Day's position.
  - **UI.** The Opening hours section sits after Contact and before Image (04, 05, 07). Off: a "Get opening hours from Google" button, only for an Attraction or Meal with a place. On: the hours with "from Google" beside them (one line when the same every day, else the Event's weekday when it has a dated Day, with a "Whole week" toggle; a note that dates are needed when the Trip has none), the conflict text beside them, and a "Remove opening hours" action. Map View (06) and Viewer (18) panels show the hours and the text read-only. The card shows the amber label and border (04) when there is a conflict. No snackbar and no dismissal. Both languages need messages.
  - **Designed (2026-10-19):** screen 44 (`design/png/44-opening-hours.png`) draws the button, loading, one-line and weekday hours, the "Whole week" list, "Remove opening hours", the no-hours and date-needed notes, read-only panels, the phone sheet, and the general conflict wording (English, with proposed Traditional Chinese).
