Design notes

  • Invitation is accepted only with a verified, matching email. Auth0 sends a verification link at sign-up but lets unverified accounts log in, so the app checks email_verified before adding an Editor.
  • Wrong account: replaces the earlier “You don’t have access to this Trip” page for invitations. “Log in as …” logs out, then opens the login page with login_hint and prompt=login. “Go to my Trips” leaves the invitation open for later.
  • Not verified: no login is blocked; only joining waits. “Send the link again” asks our API to resend the Auth0 verification email.
  • Email matches: no extra page; the Trip opens with a toast.
  • Session expired with edits: the panel stays open with what was typed. Its Save becomes “Log in to save”, which opens the login page in a popup; after login the edits are saved and the panel closes as after Save. If the popup is blocked, the edits are stored in the browser and the login page opens in the same tab; the panel comes back with them after login.
  • Loading: applies to every top bar (#01, #02, #38, #47).

Login errors

  • Auth0’s page has no Cancel. Going back from it returns to the app with no message; “Login didn’t complete” (#37 C) shows only when Auth0 returns an error.
